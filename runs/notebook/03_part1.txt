
==============================================================================
1. SHAPES: tokens -> logits -> shift -> flatten -> scalar
==============================================================================
  tokens                    (4, 256)            B sequences x T token ids
  logits                    (4, 256, 8192)      B x T positions x V scores
  inputs = tokens[:, :-1]   (4, 255)            T-1: the last token predicts nothing we have
  targets = tokens[:, 1:]   (4, 255)            T-1: the first token is predicted by nothing
  logits[:, :-1]            (4, 255, 8192)      scores aligned with targets
  flat logits               (1020, 8192)        B*(T-1) rows, one classification each
  flat targets              (1020,)             one correct class id per row
  loss                      scalar              mean over all B*(T-1) rows

  check: targets[:, t] == inputs[:, t+1] for every t  -> OK

5. PADDING MASK
==============================================================================
  Batch: 4 real documents cut to different lengths, right-padded with <pad> to T=256
    row 0: 256 real tokens +   0 pads -> 255 real targets
    row 1: 192 real tokens +  64 pads -> 191 real targets
    row 2: 128 real tokens + 128 pads -> 127 real targets
    row 3:  64 real tokens + 192 pads ->  63 real targets

  Row 3 at the edge of its real text:
   pos  input               ->  target              counted?
    60  ' W'                ->  'ile'               yes
    61  'ile'               ->  'en'                yes
    62  'en'                ->  ' W'                yes
    63  ' W'                ->  <pad>               NO (target is <pad>)
    64  <pad>               ->  <pad>               NO (target is <pad>)
    65  <pad>               ->  <pad>               NO (target is <pad>)

  how the loss is averaged                     positions      loss
  A. everything, pads included                     1,020    9.2813
  B. pads masked (correct)                           636    6.6192
  C. pads masked, but divided by B*(T-1)           1,020    4.1273
     (loss on the pad targets alone)                 384   13.6904

  C = B x 636/1020 = B x 0.624: the loss shrinks with the share of real tokens,
  which changes from batch to batch, so C is not comparable across batches.
  A is high here because this model never saw <pad> as a target. If you TRAINED with
  pads included, it would learn '<pad> follows <pad>' and A would look better than it is.

  causal check: row 3's logits alone vs. with pads after it, max |diff| = 2.86e-06
  (~0: pads sit to the RIGHT, and causal attention only looks LEFT)

6. DOCUMENT-BOUNDARY MASK
==============================================================================
  Batch: 16 windows of T=256, each containing a document boundary

                                       positions      loss
  without boundary mask                    4,080    6.4899
  with boundary mask                       4,064    6.4924

  Mean loss by kind of position:
  <eos> -> next doc (masked)                  16    5.8399
  last token -> <eos> (kept)                  16    5.7775
  everything else                          4,048    6.4953

  First 4 boundaries, with the loss on each pair:
  input               ->  target                  loss
  '.'                 ->  <eos>                  4.723  kept
  <eos>               ->  'The'                  2.194  MASKED
  'm'                 ->  <eos>                  7.548  kept
  <eos>               ->  'Ch'                   6.288  MASKED
  '.'                 ->  <eos>                  4.683  kept
  <eos>               ->  'W'                    4.760  MASKED
  ')'                 ->  <eos>                  6.114  kept
  <eos>               ->  'Re'                   7.474  MASKED

  Here the masked pairs are EASIER than average (5.84 vs 6.50).
  Documents often start the same way ('The', a title word), so even early in training
  the model has a generic start-of-document guess. Masking them RAISES the loss by +0.0026.
  In a normal random batch only ~0.08% of positions are boundaries, so the average barely
  moves either way. The size of the change isn't the point. The reason to mask is that the
  target asks the model to predict document 2 from document 1, a relationship that doesn't exist.
  Note: the loss mask doesn't stop ATTENTION from crossing the boundary. Tokens after
  <eos> can still attend to document 1; a document-aware attention mask would fix that.

  saved by tying: 3,145,728 = V x D = 8,192 x 384  (15.4% of the untied model)
  (tied: the head reuses the embedding matrix, so it adds 0 new parameters)

  Same arithmetic at the course's V5 size: 131,072 x 4,096 = 536,870,912 per matrix.
  In a small model like ours the head is a big share of all parameters; that share
  is why tying is popular at small scale.

8. ORDINARY VS CHUNKED CROSS-ENTROPY (output head + loss, forward + backward)
==============================================================================
  hidden states h: [N, D] = [16,320, 384]   (batch 64 x 255 positions)
  full logits    : [N, V] = [16,320, 8,192] = 510 MiB in fp32

  method                 logits held      loss   peak MiB  vs ordinary  median ms  max grad diff
  ordinary                    16,320    6.4910     1548.0         1.0x       70.6              -
  chunked 4096                 4,096    6.4910      423.9    3.7x less       61.9        4.2e-03
  chunked 1024                 1,024    6.4910      132.8   11.7x less       75.0        8.4e-03
  chunked 256                    256    6.4910       60.2   25.7x less      114.5        1.5e-02

  'logits held' = rows of logits in memory at once. 'max grad diff' = largest gradient
  difference vs ordinary, relative to the largest gradient. Times are the median of 3 runs.

  Loss: ordinary 6.4910 vs chunked 6.4910  (difference 0.0e+00)
  Peak memory: 1548.0 MiB -> 132.8 MiB at chunk 1024 = 11.7x less

  Time: chunk sizes faster than ordinary: [4096]; slower: [1024, 256].
  Chunking adds work (backward recomputes each chunk's logits) but removes memory traffic:
  the ordinary path writes and re-reads several full [N, V] tensors. Large chunks keep most
  of that saving for little extra work; very small chunks pay a per-chunk overhead.
  The objective is unchanged; only what exists in memory at once is different.

  Gradient check, chunk 1024 vs ordinary (max relative difference):
    bf16 (table above)  8.4e-03   bf16 keeps ~3 significant digits (relative step ~8e-3)
    fp32                7.4e-06   fp32 keeps ~7 significant digits
  -> rounding only: both methods compute the same gradients
  Smaller chunks show bigger bf16 differences because each chunk's share of the head
  gradient is rounded to bf16 before the shares are added: more chunks, more roundings.

  Bonus: this loss is run A's validation loss on 16,308 positions,
  perplexity exp(6.4910) = 659  (untrained was ~8,192)
